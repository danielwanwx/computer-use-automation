## Implemented deterministic kernel increments

- Strict Pydantic decision, observation, action-step, condition, capability, qualification, and trace models are under `src/cua/models/`.
- `src/cua/conditions/` implements strong-Kleene PASS/FAIL/UNKNOWN evaluation and a strict `USD_DECIMAL_V1` parser. Named conditions can resolve from an accepted definition map; unresolved or cyclic definitions remain UNKNOWN at runtime and are rejected by static acceptance.
- `src/cua/profiles/parabank.py`, `sessions/`, and `surface/` now consume the pinned native profile. Readiness checks use the observed overview headings Account/Balance*/Available Amount and the visible final `<tbody>` Total row; the detail label `Available:` maps to `PROFILE_AVAILABLE_BALANCE`. Session identity and account membership remain ephemeral and value-protected. Root reports the native Playwright smoke passed on Chrome channel; replay qualification remains pending.
- `src/cua/compiler/` compiles only successful traces with a matching completion proof and verified observed effects, preserving event order and IDs. Declared membership checkpoints and a final runtime-owned VERIFY marker have explicit placement; completion checks cannot be overridden by bundle conditions. The registry canonicalizes the complete bundle closure, rejects unknown/cyclic/deep condition references and undeclared operations, enforces immutable revisions, pins actual parser/profile/condition source digests, and rechecks nested content and runtime/browser/target qualification before an approved bundle is returned for execution.
- `src/cua/policy/` classifies the current runtime target independently of an artifact risk label, then intersects deployment, capability, and run origin/route/operation allowances and the currently observed control's operations. Malformed runtime classifications fail closed.
- `src/cua/verification/` implements a runtime-owned completion gate. It revalidates the current session/run/authentication generation and principal signal, checks detail origin/profile/route and pinned field/parser/currency semantics, and requires a same-run complete-overview membership proof bound to the actual requested account value. Account ID and balance are `SecretStr` values held only in memory. The verifier accepts no artifact predicates or model `DONE` decision and returns outputs only after the final native USD parse succeeds.
- Registry approval now rejects a full executable-runtime fingerprint changed since validation; approved loads also require the stored manifest digest to match the requested immutable revision before replay can dispatch.
- A serial, epoch-fenced `SessionActor`, async `SessionManager`, shared target lock, and profile-driven Playwright surface are present under `src/cua/sessions/` and `src/cua/surface/`. `SessionManager.get_state()` exposes immutable browser version metadata without UI access so replay can qualify a bundle before reading the browser session.
- `src/cua/execution/` provides one actor-serialized dispatch gateway for CLICK and EXTRACT. Live target destination is revalidated against the pinned profile; post-click readiness is polled without redispatch, and unknown effects are reconciled from a fresh observation before any approved recovery anchor is used.
- `SafeReasonCode` includes APP_ERROR, ACCESS_DENIED, AMBIGUOUS_STATE, and UNKNOWN_BLOCKER so the surface/discovery failure states have stable safe values.
- `src/cua/replay/` is model-free. It checks approval, digest, executable fingerprint, browser version, target revision, and the exact supported contract before UI access; it enforces the final runtime-owned completion verifier inside the session actor and exposes outputs only on verified success. It supports bounded, effect-aware recovery and a value-free handoff callback contract. A separate `run_validation()` entrypoint loads only static DRAFT revisions and shares that same executor, gateway, condition path, and final verifier. It requires a one-use `ValidationSessionBinding` minted by `SessionManager.prepare_validation_session()` for a principal alias in the trusted server-side validation allowlist; ordinary `prepare()` does not grant validation authority. This seam is unit-tested with synthetic UI state, not yet qualified through a real validation browser run. Application handoff wiring is present; browser-backed validation and manual takeover remain release cases.
- `InvocationResult` is shared by replay and discovery, with sensitive outputs held as `SecretStr` only for success; the input failure wire code is canonicalized to `INPUT_INVALID`.
- `pyproject.toml` discovers `tests/` and `testbed/tests/`, with both `src/` and project-root import paths; `.gitignore` excludes local environments, caches, credential files, and databases.
